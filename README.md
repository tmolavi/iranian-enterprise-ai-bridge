## این پروژه چرا ساخته شد؟

من متخصص ERP نیستم و هدف این پروژه نیز ادعای تخصص در ERP نیست.

در تعامل با سازمان‌ها، کارخانه‌ها و مجموعه‌های بزرگ تولیدی و بازرگانی، بارها با یک شکاف تکرارشونده مواجه شدم: سازمان داده بسیار زیادی در نرم‌افزارهای حسابداری، ERP، CRM، اتوماسیون اداری، سیستم‌های کنترل سالن تولید و فایل‌های داخلی اکسل داشت، اما مدیران ارشد و صاحبان کسب‌وکار نمی‌دانستند برای استفاده عملی، ایمن و قابل اتکا از هوش مصنوعی دقیقاً از کجا باید شروع کنند.

از طرف دیگر، متخصص ERP طبیعتاً دانش عمیقی از جداول، ماژول‌ها و فرآیندهای سیستم خودش دارد، اما لزوماً با معماری مدل‌های زبانی بزرگ (LLMs)، الگوهای عاملیت هوشمند (AI Agents)، بازیابی پیشرفته اسناد (RAG)، ابزارسازی کنترل‌شده (Tool Calling)، لایه معنایی حاکمیت داده (Semantic Layer) و استقرار مدل‌های محلی (Local On-Prem LLMs) آشنا نیست. از سوی سوم، مهندس هوش مصنوعی نیز بدون شناخت دقیق منطق مالی، حسابداری صنعتی و بهای تمام‌شده سازمان نمی‌تواند به‌تنهایی پاسخ‌های قابل اتکا تولید کند و خروجی‌های آن غالباً با توهمات محاسباتی همراه می‌شود.

در برخی گفتگوها حتی مسئله اصلی فناوری نبود؛ مسئله این بود که داده‌ها در جزایر سازمانی باقی می‌ماند و نیاز واقعی مدیرعامل به یک مسیر روشن، شفاف و ممیزی‌پذیر برای رسیدن از «داده‌های خام» به «تصمیمات استراتژیک» تبدیل نمی‌شد.

**این پروژه برای ساختن پلی میان این دنیاها ایجاد شده است.**

هدف آن به هیچ وجه جایگزینی ERP، متخصص ERP، واحد هوش تجاری (BI)، حسابدار، مدیر مالی یا مدیر عملیات نیست. هدف این است که هر کدام بتوانند در یک معماری منسجم نقش تخصصی خود را ایفا کنند و سازمان بتواند با اتکا به استقرار کاملاً محلی (Local On-Prem)، به حداقل رسانی داده‌ها (Data Minimization)، ماسک داده‌های حساس (PII Masking) و کنترل دسترسی سازمانی، از هوش مصنوعی برای بینش‌های لحظه‌ای و تصمیم‌گیری دقیق استفاده کند.

این پروژه به‌صورت عمومی و با مجوز **MIT**، در راستای **مسئولیت اجتماعی** و با توجه به شرایط دشوار و حساس کسب‌وکار و تولید در کشور منتشر می‌شود تا کارخانجات، تولیدکنندگان، توسعه‌دهندگان و متخصصان بتوانند آزادانه از آن بهره‌مند شوند.

## این پروژه چه ارتباطی با تحقیقات GEO / AI Visibility دارد؟

تمرکز و حوزه اصلی فعالیت و تحقیقات **تقی مولوی** بر مباحث بهینه‌سازی موتورهای هوش مصنوعی (**GEO / Generative Engine Optimization**)، دیده‌شدن در سیستم‌های جستجوی مبتنی بر هوش مصنوعی (**AI Visibility**) و بهینه‌سازی موتورهای پاسخگو (**AEO**) استوار است.

پل سازمانی هوش مصنوعی ایران (IEAB) از دل همین تحقیقات شکل گرفته است. در هر دو حوزه (چه در محیط وب عمومی و موتورهای جستجوی AI مانند Perplexity و ChatGPT، و چه در سیستم‌های داخلی سازمان و هوش مصنوعی مدیرعامل)، هسته اصلی چالش کاملاً یکسان است:

1. **اعتبارسنجی و استناد به شواهد قطعی (Grounding & Source Lineage):** هوش مصنوعی نباید توهم کند یا ارقام را حدس بزند؛ پاسخ‌ها باید مستقیماً به رکوردهای معتبر و شواهد قطعی مستند باشند.
2. **لایه معنایی و قراردادهای ساختاریافته (Semantic Contracts):** تبدیل داده‌های خام و بدون ساختار به تعاریف استاندارد و شاخص‌های شفاف.
3. **بازیابی دقیق مبتنی بر زمینه (Context Retrieval):** هدایت مدل هوش مصنوعی به سمت ابزارها و رکوردهای هدف با کمترین نویز داده‌ای.

این مخزن یک پروژه متن‌باز مستقل مهندسی داده و هوش مصنوعی برای کمک به اکوسیستم تولیدی و صنعتی کشور است و تقی مولوی هیچ‌گونه خدمات فروش، نمایندگی یا پیاده‌سازی نرم‌افزارهای تجاری ERP ارائه نمی‌دهد.

## اصل مهندسی غیرقابل‌مذاکره: LLM پایگاه داده یا ماشین‌حساب نیست!

یکی از بزرگ‌ترین اشتباهات رایج، اتصال مستقیم مدل زبانی (LLM) به پایگاه داده عملیاتی ERP و درخواست نوشتن خودکار کوئری‌های SQL آزاد است. در این پروژه چنین معماری خطرناکی **مطلقا ممنوع** است:

```
❌ معماری نادرست و خطرناک:
مدیرعامل ──> پرسش ──> مدل زبانی (LLM) ──> اجرای SQL آزاد روی دیتابیس عملیاتی ERP! (ریسک خرابی، قفل شدن دیتابیس و توهم عددی)

✅ معماری استاندارد پل سازمانی (IEAB):
سامانه‌های سازمانی (راهکاران / دیدگاه / شماران / سپیدار / SQL Server)
       ↓ (اتصال صرفاً خواندنی / Read Replica / CDC / خروجی کنترل‌شده)
خط لوله یکسان‌سازی داده‌ها (Canonical Enterprise Model)
       ↓
لایه معنایی و مخزن تعاریف شاخص‌ها (Semantic Layer - تحت مالکیت CFO / COO)
       ↓
موتورهای محاسباتی قطعی و ارزیابی تطبیق مالی (Deterministic Metrics & Reconciliation Gate)
       ↓
درگاه ابزارها و کنترل دسترسی سازمانی (AI Tool Gateway & Policy Engine)
       ↓
مدل زبانی هوش مصنوعی (تنها برای درک نیت، انتخاب ابزار و سنتز توضیحات)
       ↓
میز کار اجرایی مدیرعامل (همراه با شواهد قطعی، تفکیک ریشه‌ای و رهگیری اسناد)
```

**مدل زبانی (LLM) سیستم حسابداری، دفترکل، انباردار یا ماشین‌حساب سازمان نیست.**  
سیستم‌های قطعی ارقام دقیق را محاسبه می‌کنند؛ هوش مصنوعی نیت سؤال را می‌فهمد، ابزار معتبر را فرامی‌خواند و پاسخ را با ارجاع دقیق به شواهد توضیح می‌دهد.

## ویژگی‌های کلیدی پلتفرم

1. **مدل داده استاندارد کاننیکال (Canonical Data Model):** پوشش جامع ۱۱ دامنه سازمانی شامل ساختار سازمانی، طرف‌های تجاری، فروش، تدارکات، انبار و کاردکس، خزانه‌داری، حسابداری مالی، تولید و OEE، منابع انسانی و اسناد/صورتجلسات.
2. **لایه معنایی مصوب (CFO/COO Semantic Contracts):** کلیه شاخص‌های کلیدی (سود ناخالص، فروش خالص، دوره وصول مطالبات DSO، OEE خطوط تولید، نرخ ضایعات و پیش‌بینی نقدینگی) دارای فرمول نسخه شده و مصوب هستند.
3. **قابلیت کنترل تطبیق مالی (Subledger to GL Reconciliation Capability):** معماری IEAB امکان ارزیابی تطبیق گزارش‌های زیرسیستم‌ها با اسناد دوبل دفتر کل و ثبت وضعیت اعتبارسنجی را فراهم می‌کند.
4. **استقلال کامل از تأمین‌کننده AI و استقرار محلی (Fully On-Premises):** پشتیبانی بومی از سرورهای محلی vLLM / Ollama با مدل‌های متن‌باز (مانند DeepSeek-R1 و Qwen 2.5) روی سخت‌افزارهای داخلی جهت جلوگیری از خروج داده‌های سازمانی.
5. **امنیت و ممیزی معکوس (Auditability & PII Masking):** ماسک خودکار کدملی، شماره شبا، شماره همراه و حقوق، همراه با لاگ تغییرناپذیر کلیه ابزارهای فراخوانی‌شده و ارقام خروجی.
6. **معماری، SDK و Scaffold کانکتورهای نرم‌افزارهای سازمانی ایران:** الگوهای یکپارچه‌سازی، قراردادها و اسکلت آماده برای SQL Server، راهکاران همکاران سیستم، دیدگاه چارگون، شماران سیستم، سپیدار، پیام‌گستر، دیدار، Odoo بومی و فایل‌های اکسل/CSV.
7. **میز کار اجرایی پنج‌گانه مدیرعامل:**
   - **اکنون (Now):** وضعیت لحظه‌ای شاخص‌های حیاتی سازمان
   - **استثنائات (Exceptions):** انحرافات و هشدارهای نیازمند مداخله فوری
   - **چرا (Why):** درخت تحلیل ریشه‌ای و تفکیک ابعادی عوامل کاهش یا افزایش
   - **آینده (Next):** برآورد جریان نقدینگی ۳۰ روزه و نقاط ریسک کسری
   - **پرسش (Ask):** گفتگوی طبیعی به زبان فارسی با ارائه فوری شواهد و رهگیری اسناد

## شروع سریع (Quick Start)

### ۱. نیازمندی‌ها
- Node.js نسخه 20 یا بالاتر
- دسترسی به پایگاه داده یا کپی خواندنی (Read Replica) نرم‌افزار سازمانی

### ۲. کلون و نصب وابستگی‌ها
```bash
git clone https://github.com/tmolavi/iranian-enterprise-ai-bridge.git
cd iranian-enterprise-ai-bridge
npm install
```

### ۳. ساخت پکیج‌ها و اجرای تست‌ها
```bash
npm run build
npm test
```

### ۴. اجرای بنچمارک آزمایشی هوش مصنوعی مدیرعامل (Executable Cases)
```bash
npm run benchmark
```
> **توضیح:** این دستور ۱۵ سناریوی اجرایی نمونه را بر روی دیتاست فیکسچر سازمانی ارزیابی می‌کند. کاتالوگ کامل ۱۰۰ پرسش استراتژیک در [docs/fa/CEO-QUESTIONS.md](docs/fa/CEO-QUESTIONS.md) مستند شده است.

### ۵. اجرای ویزارد ارزیابی و استقرار سازمان
```bash
npm run wizard
```

### ۶. راه‌اندازی سرور API و وب‌اپلیکیشن مدیرعامل
```bash
# ترمینال ۱: اجرای سرور API (پورت ۳۰۰۰)
npm run start:api

# ترمینال ۲: اجرای میز کار وب مدیرعامل (پورت ۳۰۰۱)
node apps/executive-web/server.js
```
سپس مرورگر خود را در آدرس `http://localhost:3001` باز کنید.

## استقرار با Docker Compose

```bash
docker-compose up -d
```
این دستور پایگاه داده PostgreSQL مجهز به pgvector، حافظه موقت Redis، سرور API و وب‌سایت مدیرعامل را در کانتینرهای ایزوله بالا می‌آورد. (پایگاه داده PostgreSQL و Redis اختیاری بوده و سیستم در حالت پیش‌فرض به صورت مستقل با فیکسچرهای درون‌حافظه‌ای کار می‌کند).

## راهنمای سازمان‌ها: از کجا شروع کنیم؟

### اگر قبلاً ERP خریده‌اید:
۱. سند [راهنمای پیاده‌سازی گام‌به‌گام (Implementation Playbook)](docs/fa/IMPLEMENTATION-PLAYBOOK.md) را مطالعه کنید.
۲. با کمک ویزارد سازمان (`npm run wizard`)، نوع اتصال خواندنی به پایگاه داده را انتخاب کنید.
۳. لایه معنایی شاخص‌های مالی را با مدیر مالی (CFO) نهایی کنید.

### اگر در حال خرید ERP هستید:
پیش از عقد قرارداد با شرکت‌های نرم‌افزاری، [چک‌لیست استعلام و خرید ERP (RFP Checklist)](docs/fa/RFP-CHECKLIST.md) را در اختیار تیم بازرگانی و IT قرار دهید تا از قفل شدن دسترسی به داده‌ها (Vendor Lock-in) جلوگیری شود.
